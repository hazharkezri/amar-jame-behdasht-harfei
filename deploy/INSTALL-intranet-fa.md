# راهنمای نصب روی سرور داخل شبکه‌ی دانشگاه

این راهنما برای حالتی است که سامانه روی یک سرور داخل شبکه‌ی دانشگاه بالا می‌آید و کاربران با آدرس داخلی (مثل `http://192.168.0.200:3000` یا یک دامنه‌ی داخلی) به آن دسترسی دارند.

---

## ۱. پیش‌نیازها

- Node.js نسخه **۲۲٫۵ یا بالاتر** (نسخه‌ی ۲۴ تأیید شده)
- بدون هیچ وابستگی خارجی npm — پروژه کاملاً خوداتکاست
- دسترسی خواندن/نوشتن به پوشه‌ی پروژه
- فایروال: پورت `3000` (یا پورت nginx) باید برای شبکه‌ی داخلی باز باشد

بررسی سریع:

```
node -v
```

---

## ۲. نصب فایل‌ها

پوشه‌ی `amar-system` را روی سرور کپی کنید (از طریق USB، SCP یا فشرده‌سازی). سپس:

```
cd amar-system
copy .env.example .env
```

فایل `.env` را ویرایش کنید و موارد زیر را تنظیم نمایید:

```
APP_SECRET=<یک رشته تصادفی ۶۴ رقمی>
PORT=3000
HOST=0.0.0.0
TRUST_PROXY=0
COOKIE_SECURE=0
ALLOWED_EMAIL_DOMAINS=ac.ir,gov.ir
DB_FILE=data/app.db
```

### توضیح مهم درباره‌ی هر مورد

**`APP_SECRET`** مهم‌ترین مقدار است. با دستور زیر بسازید:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> اگر این کلید گم شود یا عوض شود، کدملی‌ها و کلیدهای احراز هویت دومرحله‌ای کاربران **غیرقابل بازیابی** می‌شوند. حتماً نسخه‌ی پشتیبان جداگانه نگه دارید.

**`COOKIE_SECURE=0`** چون روی HTTP هستیم. اگر بعداً HTTPS گذاشتید، این را به `1` تغییر دهید، وگرنه کوکی ورود اصلاً ثبت نمی‌شود و هیچ‌کس نمی‌تواند وارد شود.

**`TRUST_PROXY=0`** تا وقتی nginx جلوی سامانه نیست. اگر nginx اضافه کردید، `1` کنید تا آیپی واقعی کاربر در لاگ ممیزی درست ثبت شود.

**`HOST=0.0.0.0`** تا از بیرونِ سرور (دستگاه‌های دیگر شبکه) قابل دسترسی باشد. فقط `127.0.0.1` یعنی خودِ سرور.

## ۳. راه‌اندازی اولیه

**الف) ساخت حساب مسئول ستاد** (فقط یک بار):

```
node --no-warnings scripts/create-root.js 1387140175 "نام و نام خانوادگی" name@umsu.ac.ir
```

خروجی، **رمز موقت** و **کلید احراز هویت** را چاپ می‌کند. کلید را در برنامه‌ی Authenticator گوشی وارد کنید و رمز موقت را نگه دارید.

**ب) ساخت ۱۹ شهرستان:**

```
node --no-warnings scripts/seed-urmia.js
```

**پ) تست کامل** (باید آخرش `ALL SMOKE TESTS PASSED` بدهد):

```
npm test
```

**ت) اجرا:**

```
npm start
```

حالا از یک دستگاه دیگر داخل شبکه باز کنید:

```
http://192.168.0.200:3000
```

(آیپی را با آیپی سرور خود عوض کنید.)

## ۴. اجرای دائمی (بدون بستن پنجره)

### روش الف — Windows Task Scheduler (پیشنهادی برای سرور ویندوز)

۱. `taskschd.msc` را باز کنید
۲. Create Task → General → تیک **Run whether user is logged on or not**
۳. Triggers → At startup
۴. Actions → Program: `node`، Arguments: `--no-warnings server.js`، Start in: مسیر پوشه‌ی `amar-system`
۵. Conditions → تیک **Start the task only if the computer is on AC power** را بردارید

نکته: متغیرهای `.env` باید در سطح سیستم تنظیم شوند (`setx APP_SECRET ...`) چون Task Scheduler آن‌ها را از فایل `.env` نمی‌خواند. روش ساده‌تر: یک فایل `run.bat` بسازید:

```bat
@echo off
cd /d "%~dp0"
set APP_SECRET=کلید_اینجا
set PORT=3000
set HOST=0.0.0.0
set COOKIE_SECURE=0
set TRUST_PROXY=0
node --no-warnings server.js
```

و در Task Scheduler همین `run.bat` را اجرا کنید.

### روش ب — لینوکس با systemd

فایل `deploy/amar.service` را در `/etc/systemd/system/` کپی و مسیرها را اصلاح کنید:

```
sudo systemctl daemon-reload
sudo systemctl enable --now amar
sudo systemctl status amar
```

## ۵. پشتیبان‌گیری خودکار

```
node deploy/backup.js
```

- دیتابیس با `VACUUM INTO` کپی می‌شود؛ این روش حتی موقع اجرای سامانه امن است و ردیف‌های WAL را از دست نمی‌دهد.
- فایل‌های داده (`indicators.json`، `tables.json`، `report.json`) هم کپی می‌شوند.
- پیش‌فرض ۳۰ نسخه نگه داشته می‌شود (`KEEP=30`).
- خروجی: `data/backup/app-<تاریخ>.db`

**خودکارسازی:**

ویندوز — Task Scheduler با دستور:

```
powershell -ExecutionPolicy Bypass -Command "node 'C:\مسیر\amar-system\deploy\backup.js'"
```

زمان‌بندی: روزانه ساعت ۲ بامداد.

لینوکس — cron:

```
0 2 * * * cd /opt/amar-system && /usr/bin/node deploy/backup.js
```

> مهم: پشتیبان را فقط داخل همان سرور نگذارید. هفته‌ای یک‌بار نسخه را به رایانه‌ی دیگر یا فضای ذخیره‌سازی شبکه منتقل کنید.

## ۶. نکته‌های مهم درباره‌ی HTTP داخلی

**چه چیزهایی روی HTTP کار می‌کند:**

- ورود با کد ملی + رمز + کد TOTP ✔
- ورود آمار، ذخیره، ارسال و تأیید ✔
- خروجی و درون‌ریزی اکسل ✔
- داشبورد و گزارش‌ها ✔
- فونت وزیرمتن، استایل‌ها و منوها ✔

**چه چیزهایی روی HTTP کار نمی‌کند:**

- قابلیت **آفلاین** و **نصب روی موبایل** (PWA). مرورگر فقط روی HTTPS یا `localhost` اجازه‌ی ثبت Service Worker می‌دهد. سامانه بدون آن هم کاملاً کار می‌کند، فقط اگر شبکه قطع شود صفحه از حافظه‌ی کش باز نمی‌شود.
- رمزنگاری ترافیک. هر کسی داخل شبکه بتواند ترافیک را رصد کند، محتوا را می‌بیند. روی شبکه‌ی داخلی معمولاً قابل قبول است، ولی اگر مقررات دانشگاه ایجاب می‌کند، از HTTPS داخلی استفاده کنید.

**پیشنهاد برای فعال‌کردن HTTPS داخلی:**

اگر دانشگاه CA داخلی دارد، گواهی بگیرید. در غیر این صورت با openssl یک گواهی خودامضا بسازید و آن را روی دستگاه‌های کاربران «مورد اعتماد» کنید:

```
openssl req -x509 -newkey rsa:2048 -nodes -days 825 -keyout privkey.pem -out fullchain.pem -subj "/CN=amar.local"
```

بعد `COOKIE_SECURE=1` کنید و `deploy/nginx.conf` را فعال نمایید.

**یک هشدار بی‌خطر:** در کنسول مرورگر ممکن است پیام `Cross-Origin-Opener-Policy header has been ignored` ببینید. این فقط به این دلیل است که مرورگر هدرهای امنیتی مربوط به HTTPS را روی HTTP نادیده می‌گیرد. مشکلی در کار ایجاد نمی‌کند.

## ۷. عیب‌یابی سریع

| مشکل | دلیل | راه‌حل |
|---|---|---|
| `APP_SECRET تنظیم نشده` | متغیر محیطی خالی است | مقدار `.env` را پر کنید |
| ورود موفق می‌شود ولی صفحه خالی می‌ماند | `COOKIE_SECURE=1` روی HTTP | `COOKIE_SECURE=0` |
| از دستگاه دیگر باز نمی‌شود | `HOST=127.0.0.1` یا فایروال | `HOST=0.0.0.0` + باز کردن پورت |
| «این دوره بسته است» و فیلدها غیرفعال | دوره‌ای ساخته نشده | «مدیریت ستاد ← دوره‌های آماری ← دوره‌ی جدید» |
| خطا در `npm test` | Node قدیمی | ارتقا به Node ۲۲٫۵+ |
| فونت‌ها عجیب به نظر می‌رسند | فایل‌های `public/fonts` کپی نشده | پوشه‌ی `fonts` را بررسی کنید |

## ۸. چک‌لیست پیش از بهره‌برداری

- `npm test` بدون خطا اجرا شود
- `APP_SECRET` در جای امنی نگهداری شود
- بکاپ روزانه زمان‌بندی و **خارج از همان سرور** نگهداری شود
- آیپی و پورت در اختیار همه‌ی کاربران مجاز قرار گیرد
- فایروال فقط پورت لازم را باز کند
- پس از اولین ورود، رمز موقت عوض شود
- ممیزی امنیتی مستقل پیش از بهره‌برداری رسمی انجام شود
